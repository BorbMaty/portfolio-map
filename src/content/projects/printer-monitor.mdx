## Problem

A 3D print can run for hours, and it usually runs unattended. When it fails (the filament turns into spaghetti, a layer
shifts, the part comes off the bed), the printer keeps going: it wastes material and time, and it can damage the machine.
Nobody notices until they come back.

## What I built

A monitoring system that watches the printer with three cameras and recognises nine kinds of failure in real time. The
model is a YOLOv8x network I trained on a dataset I captured and annotated myself. It reaches 89.2 % mAP50 and 83.6 %
recall, and it takes about 23 ms to analyse a frame.

The four failures that ruin a print (spaghetti, not sticking, layer shift, warping) send an email straight away; the
others are logged to a live dashboard. The dashboard shows the three camera streams over WebRTC with the detections on
top, and an inference log with every analysed frame. A switch on the dashboard pauses capture remotely.

## Architecture

The edge is a Raspberry Pi 4B. MediaMTX turns the three camera feeds into WebRTC streams, published through a Cloudflare
tunnel, and a small Python service sends frames to Google Cloud Pub/Sub.

In the cloud, a dispatcher Cloud Function forwards each frame to a Vertex AI endpoint that runs the model on a T4 GPU, and
drops frames older than 5 s, so a restarted model is not flooded by a backlog. The model publishes its result for every
frame, empty or not; a second Cloud Function stores it in Firestore, raises alerts and sends the emails. The dashboard is
a plain JavaScript page on Firebase Hosting that listens to Firestore. All of the infrastructure is defined in Terraform.

## What I learned

Building the whole path, from a camera on the printer to an alert email, taught me that the model is the smallest
part of a working system. Most of the effort went into what happens around it: getting frames reliably off the Pi,
keeping a GPU endpoint from drowning in a backlog, and keeping its cost under control, since the T4 GPU is the only part
that really costs money.
